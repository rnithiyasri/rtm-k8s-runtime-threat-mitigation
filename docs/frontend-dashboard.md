# RTM Operational Dashboard Documentation

## Overview

The **RTM Operational Dashboard** provides real-time, read-only observability into the Runtime Threat Mitigation engine running in the Kubernetes cluster. It bridges kernel-level detection telemetry from Falco with automated containment actions executed by the controller.

---

## 1. What the Dashboard Displays

1. **Pipeline Strip (7 Stages)**:
   - **Stage 1 (Attack Trigger)**: Real-world attack scenario execution (human-in-the-loop).
   - **Stage 2 (Falco eBPF Detect)**: Highlights when an alert has been generated by the kernel driver.
   - **Stage 3 (Falcosidekick Forward)**: Shows successful delivery to the controller webhook.
   - **Stage 4 (Controller Receive)**: Shows alert receipt and timestamp ingestion.
   - **Stage 5 (Dedupe & Decide)**: Confirms alert deduplication evaluation and graduated response policy selection.
   - **Stage 6 (Safety Gate)**: Evaluates namespace, opt-in label barrier (`rtm.enforce=true`), and `DRY_RUN` mode. Displays warning if blocked by a safety gate.
   - **Stage 7 (Mitigation Action)**: Confirms whether `isolate_network` (NetworkPolicy) or `kill_pod` was executed.

2. **Live Alert History Table**:
   - Queries `GET /alerts/recent` on the controller.
   - Columns: `Time`, `Rule ID`, `Pod`, `Priority`, `Hint`, `Dedupe`, `Mode (Dry/Live)`, `Gate`, `Action Taken`, `Gate Reason`.
   - Flashes incoming alert rows dynamically upon receipt.

3. **Monitored Workloads (Pod Grid)**:
   - Queries `GET /pods/status?namespace=shop`.
   - Cards display pod name, phase (`Running`, etc.), restart counts, and status pills for:
     - `rtm.enforce=true` (Green)
     - `rtm.tier=restrict` (Yellow - network isolated)
     - `no enforce label` (Muted - protected by safety gate)

4. **Live Controller Config Banner**:
   - Queries `GET /config`.
   - Displays active `STRATEGY` (`graduated`, `detect_only`, `always_delete`), `DRY_RUN` state (`true`/`false`), and `ENFORCE_LABEL_SELECTOR`.

5. **Adversary Emulation Terminal Reference**:
   - Static panel showing real `kubectl exec` commands from `scripts/simulate-attacks.sh` (E1 shell spawn, E2 credential access, E3 binary drop, E4 reverse shell).
   - Includes one-click copy buttons for operator testing.

6. **Staleness & Fault State**:
   - Live health indicator:
     - **Green (`Connected`)**: Active polls succeeding within 2.5 s.
     - **Amber (`Stale`)**: Poll failed, but under 10 seconds since last heartbeat.
     - **Red (`Offline`)**: Controller unreachable for >10 seconds; displays prominent error banner.

---

## 2. Security & Non-Goals

- **No write operations**: The dashboard cannot trigger attacks, alter controller configuration, patch pods, or delete workloads.
- **Zero RBAC expansion**: Backend endpoints (`/pods/status`, `/config`, `/alerts/recent`) require only read permissions (`list`, `get` on pods in `shop`) already granted to the controller ServiceAccount.
- **No synthetic claims**: No hardcoded 100% metrics or static counters.
